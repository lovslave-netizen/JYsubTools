# 인코딩 도구 (H.265)

작성: 2026-09-26

## 목적
폴더를 스캔해서 코덱/비트레이트를 보고, 선택한 영상만 H.265(HEVC)로 다시 인코딩한다.
해상도·오디오·자막은 그대로 두고 영상 코덱만 바꾼다.

## 파일
| 경로 | 설명 |
|---|---|
| `E:\파이썬\인코딩도구\인코딩도구.pyw` | 소스 (Python tkinter) |
| `E:\파이썬\인코딩도구\build.bat` | exe 빌드 (PyInstaller, ffmpeg/ffprobe 번들) |
| `E:\파이썬\인코딩도구\bin\ffmpeg.exe, ffprobe.exe` | gyan.dev essentials 빌드 (libx265, hevc_qsv, hevc_amf 포함) |
| `E:\파이썬\인코딩도구\dist\인코딩도구.exe` | 결과물 (약 84MB, 이거 하나만 복사하면 됨) |
| `%APPDATA%\인코딩도구.json` | 마지막 사용한 인코더/품질/프리셋 저장 |

## 사용법
1. 폴더 스캔(하위 포함) / 파일 추가 → 목록에 코덱, 비트레이트, 해상도, 크기 표시
2. 체크박스로 대상 선택 (H.265 아닌 것은 기본 체크). 열 제목 클릭 = 정렬, 우클릭 = 메뉴
3. 인코더 선택 후 "선택 항목 인코딩 시작"
4. 결과는 원본 옆에 `h265_이름.mkv/mp4` (원본은 유지)
5. "원본↔결과 비교"로 코덱/비트레이트/길이/크기와 감소율 확인
6. "줄어든 원본 삭제": 체크된 원본 중 결과가 있고 실제로 줄어든 것만 휴지통으로

## 정렬
- 상단 "정렬" 콤보박스: 이름순 / 코덱순(H.265 마지막) / 인코딩 안 한 것 먼저 / 비트레이트 높은순 / 크기 큰순 / 감소율 큰순. 스캔이 끝나면 자동 적용
- 열 제목 클릭으로도 정렬 가능 (다시 클릭하면 반대 방향)

## 예상 시간 (목록 하단 요약줄)
- 선택한(아직 안 끝난) 항목의 "전체 재생시간 / 예상 인코딩 시간 / 예상 완료(날짜·시각)"을 자동 표시. 체크/해제·삭제·인코더·프리셋 변경·진행 중에 실시간 갱신
- 속도는 파일 하나 끝날 때마다 실측(재생시간x픽셀수 / 걸린 시간)해서 인코더+프리셋별로 이동평균 저장(설정 json의 speed). 그래서 해당 조합의 **첫 인코딩 전에는 예상 시간이 안 나오고** "첫 인코딩 후 계산됩니다"로 표시. 3초 미만 걸린 파일은 측정에서 제외
- 해상도가 크면 오래 걸리는 점을 반영(4K 파일은 1080p보다 4배 작업량으로 계산)

## 결과가 원본보다 커진 경우
- 인코딩 결과 크기 >= 원본이면 의미가 없으므로: 옵션 "원본보다 커지면 결과 자동 삭제"(기본 켜짐, 저장됨) → 결과(h265_...)를 **휴지통 없이 완전 삭제**, 상태 "커져서 삭제됨 (+N%)", 원본은 그대로
- 옵션을 끄면 결과를 남기고 "커짐 (+N%) 결과 삭제 권장" 표시 → 상단 "커진 결과 삭제" 버튼으로 일괄 완전 삭제(확인창 있음). (원본 삭제만 휴지통 사용)
- **기록(로그)**: 커졌던 원본은 경로, 크기, 수정시각, 커진 %, 인코더, 품질, 프리셋, 날짜를 설정 json의 bigger에 저장. 원본이 바뀌면(크기나 수정시각이 다르면) 기록은 무효
- 다시 스캔하면 기본 체크 해제 + 상태 "이전에 N% 커져서 제외". "전체 선택"과 "H.265 아닌 것만 선택"에도 자동 제외됨
- 그래도 사용자가 직접 체크하고 시작하면 경고창: 파일별로 "+388% 커짐 (CPU, 품질 16, medium, 날짜)"를 보여 주고 예(전부 인코딩) 아니오(이 파일만 빼고 진행) 취소 중 선택. 이번에 결과가 줄어들면 기록은 자동 해제
- "줄어든 원본 삭제"는 결과가 안 줄어든 항목을 원래부터 제외하므로 커진 파일의 원본은 안 지워짐

## 완료 후 동작
- 설정창의 "완료 후": 아무것도 안 함(기본) / 시스템 종료. 인코딩 시작 전에 골라 둔다
- 시스템 종료: 전부 끝나면 60초 카운트다운 창(최상단) → 취소 가능, 취소하면 옵션이 "아무것도 안 함"으로 복귀
- "중지"를 눌러 멈춘 경우에는 종료하지 않음. 이 옵션은 안전상 저장하지 않고 매번 기본값으로 시작

## 인코더
| 선택 | ffmpeg | PC | 기본 품질값 |
|---|---|---|---|
| CPU | libx265 (-crf) | 회사 PC(i5-10400) 등 | 23 |
| N150 | hevc_qsv (-global_quality) | 미니PC | 24 |
| 9070XT | hevc_amf (-rc cqp) | 집PC | 24 |

- 품질값은 낮을수록 고화질/큰 용량. 프리셋 slow/medium/fast, 기본 medium (AMF는 quality/balanced/speed로 대응)
- 회사 PC는 i5-10400 내장그래픽이 있지만 **CPU(libx265)로 인코딩**하기로 함. 코드 변경 없이 "CPU" 선택
- 10bit 원본은 10bit로 유지 (CPU yuv420p10le, GPU p010le)
- 태그 hvc1 (mp4 호환), 진행 중에는 `h265_이름.part.mp4` 임시 파일로 쓰고 성공하면 이름 변경

## 동작 규칙
- 결과 파일명은 앞에 `h265_` 접두사 (예: `영화.mp4` → `h265_영화.mp4`, 이름순 정렬 시 모임). 스캔 목록에서는 `h265_` 파일을 숨기고 원본 행에 연결
- 스캔 캐시 `%APPDATA%\인코딩도구_cache.json`: ffprobe 결과를 (경로+크기+수정시각)으로 저장해 재스캔이 빠름. 파일 존재/결과 연결은 매번 실제 파일로 확인하므로 수동 삭제·이동해도 안전
- 결과 파일이 이미 있으면 건너뜀 (스캔 시 기존 결과를 비교 대상으로 자동 연결)
- 원본 삭제 안전장치: 결과가 원본보다 안 줄었거나, 결과 길이가 원본과 2초 넘게 다르면 삭제 대상에서 제외
- 인코딩 성공 시 결과 파일의 만든/수정/액세스 날짜를 원본과 똑같이 복사 (촬영일 등 메타데이터는 -map_metadata 0 으로 유지)
- mkv 출력은 전체 스트림 복사(`-map 0 -c copy`), mp4는 영상/오디오/자막(mov_text)만
- 확장자가 mp4/mkv가 아니면(avi, ts 등) mkv로 저장

- 목록에 **합치기** 열 추가. 체크(☑)한 파일 중 합치기 표시를 한 것(2개 이상)은 목록에 보이는 순서대로 이어 붙여 **파일 1개**로 인코딩하고, 합치기 표시가 없는 나머지는 기존처럼 각각 따로 인코딩 (같은 인코더/품질/프리셋 적용). 예: 10개 중 1~4번만 합치기 표시 → 1~4번은 1개 파일, 5~10번은 6개 파일
- 표시 방법: 합치기 열 클릭(자동으로 체크도 됨) / 여러 행 선택 후 우클릭 "선택한 행 합치기". 순서는 우클릭 "위로/아래로 이동" 으로 바꿈. 시작 누르면 순서/결과 이름 확인창이 뜸. 묶음은 여러 개 가능(아래 참고)
- 결과 이름: `h265_합침_<첫파일명>_외N개.mp4/mkv` (첫 파일 폴더에 저장, 스캔 목록에서는 h265_ 접두사라 숨겨짐)
- 방식: ffmpeg concat 필터로 재인코딩. 해상도/코덱/fps가 달라도 됨(해상도는 첫 영상 기준, 다르면 비율 유지+검은 여백, fps도 첫 영상 기준). 음성 없는 영상은 무음으로 채움. 음성은 AAC 192k로 다시 인코딩, 자막/챕터는 버림. 폰 영상의 회전 정보를 반영한 화면 방향 기준으로 해상도 표시(probe 개선, 스캔 캐시는 음성정보가 없는 옛 항목만 다시 읽음)
- 결과가 원본 합계보다 커지면 "원본보다 커지면 자동 삭제" 옵션 적용 (합친 건 bigger 기록은 안 남김)
- 줄어든 원본 삭제: 합쳐진 멤버를 체크하고 누르면 합친 파일의 크기(줄었는지)와 길이(원본 합계와 일치)를 검증한 뒤 휴지통으로
- 검증: 합성 영상(해상도 다름 + 음성 없음)으로 합치기 명령 실행 → 길이 합 5.0초, 640x360, 음성 포함 hevc 확인. GUI 목록에서 합치기 표시 → 확인창 → 작업 실행(결과가 커서 자동 삭제되는 경로)까지 확인. **미검증**: 줄어든 합침 결과 + 원본 삭제 경로, 실제 큰 영상, 위로/아래로 이동 화면 확인

## 인코딩 중 대기열 편집 (2026-10-07)
- 인코딩이 돌아가는 중에도 "폴더 스캔 / 파일 추가"가 되고, 새 파일은 (체크된 것만) **대기열 맨 뒤**에 붙음 (이때는 정렬을 다시 하지 않아 목록 맨 아래에 남음). 대기 중 항목 상태는 "대기 중"
- 아직 시작 안 한 항목은 Delete/우클릭 "목록에서 제거", 체크 해제(대기열에서 빠짐), 체크(대기열 맨 뒤로), 하단 "대기 항목 모두 제거" 버튼(확인창 후 대기 전부 목록에서 제거)으로 뺄 수 있음. **지금 인코딩 중인 파일은 건드릴 수 없음**(제거 불가) — 그건 "중지"로 멈춤
- 인코딩 중 막아 둔 것: 목록 비우기, 전체 선택/해제, H.265 아닌 것만 선택, 합치기 표시/순서 이동 (대기열과 어긋나지 않게)
- 구조: 대기열 `self.queue`(작업 리스트, qlock 보호) 에서 작업자가 하나씩 꺼내 처리. 모두 끝나는 순간에 추가한 파일은 대기열에 안 들어가므로 다시 시작을 눌러야 함
- 검증: 합성 영상으로 실행해 확인 — 인코딩 중 파일 추가(맨 뒤 대기), 진행 중 항목 제거 차단, 대기 항목 제거/체크 해제/재체크, 대기 전부 제거 후 진행 중이던 파일은 끝까지 완료

### 합치기 묶음 여러 개 (2026-10-07)
- 합치기 열에는 **묶음 번호**(☐ / 1 / 2 / 3…)가 표시되고, **같은 번호끼리 하나의 파일**로 합쳐짐. 예: 1~3번 = 묶음 1, 4~6번 = 묶음 2 → 파일 2개
- 번호 지정: 합치기 열을 클릭할 때마다 ☐ → 1 → 2 → … (다른 행이 쓰는 가장 큰 번호+1 까지) → ☐ 로 순환. 또는 여러 행 선택 후 우클릭 "선택한 행을 하나로 합치기 (새 묶음)" (선택한 행 전부가 새 번호를 받음)
- 번호가 있어도 "선택"이 해제되면 제외, 한 묶음에 선택된 행이 1개뿐이면 그냥 따로 인코딩. 시작 시 확인창에 묶음별 순서/결과 이름이 나옴
- 검증: 6개 파일을 클릭으로 묶음 1(3개)/묶음 2(2개)/단독 1개로 지정 → 결과 3개(`h265_합침_m1_외2개`, `h265_합침_m4_외1개`, `h265_m6`) 생성 확인

### 합친 결과의 감소율 / 원본 묶음 삭제 (2026-10-11)
- 합치기가 끝나면 묶음의 각 행에 **결과 크기(합친 파일)** 와 **감소율(합친 결과 ÷ 묶음 원본 합계)** 이 표시되고 상태도 `합침 완료 (-84%)`. 커졌으면 `+N%`
- **기록 저장**: 합친 결과는 설정 json 의 `merges` (결과 경로 -> 원본 멤버 경로/크기/수정시각, 결과 크기, 원본 합계, 길이)에 남김. 프로그램을 껐다 켜고 다시 스캔해도 원본이 그대로이고 결과 파일이 그대로면 `합쳐서 인코딩됨 (-84%)` 로 복원되어 원본 삭제 가능. 원본이 바뀌었거나 결과 파일이 없어지면 복원 안 함
- **줄어든 원본 삭제**: 묶음 멤버 중 **하나만 체크해도 묶음 전체 원본**이 대상. 먼저 합친 결과가 원본 합계보다 작은지, 길이가 합계와 맞는지(오차 max(2초, 0.5초×개수)) 검증하고, 확인창에 묶음 요약과 확보 용량(원본 합계 - 합친 파일 크기)을 보여 준 뒤 휴지통으로. 목록에서 이미 뺀 원본이 있으면 그건 삭제 안 되고 확인창에 개수 표시
- 정렬(감소율 큰순, 열 클릭)도 합친 결과를 같은 기준으로 반영
- 검증: 720p 영상 3개를 묶음으로 합쳐 HEVC → 22.4MB(-84%) 표시, 앱을 껐다 켜서 재스캔하면 복원, 멤버 1개(x2)만 체크하고 원본 삭제 → 3개 모두 휴지통으로 가고 합친 파일과 무관한 x4는 그대로 확인

### 예전에 합쳐서 만든 `h265_합침_` 결과 찾아 연결 (2026-10-11)
- 기록(`merges`)이 없던 시절(v0.1.4 까지)에 합친 결과도, **폴더 스캔 / 파일 추가** 때 `h265_합침_<첫파일>_외N개.mp4/mkv` 를 찾아 원본과 자동으로 짝지음 (목록에는 안 올림)
- 짝짓는 규칙: 같은 폴더에서 첫 파일부터 **이름순으로 N+1개**를 묶고, 그 길이 합이 합친 결과 길이와 맞을 때(오차 max(2초, 0.5초×개수))만 연결. 맞지 않으면 연결하지 않음(합칠 때 순서를 바꿨거나 원본이 다른 폴더에 있는 경우). 연결되면 결과 크기/감소율/상태 `합쳐서 인코딩됨 (-84%)` 가 표시되고 설정(`merges`)에 저장됨. 스캔이 끝나면 하단에 "이전 합치기 결과 N개 연결"
- 원본 삭제 때는 한 번 더 검증(크기 줄었는지, 길이 일치)하므로 잘못 연결돼도 그대로 지워지지는 않음
- 검증: 기록 파일을 지운 상태에서 원본 3개 + 예전에 만든 합침 파일이 있는 폴더를 스캔 -> 자동 연결, 원본 삭제 시 3개 모두 휴지통

### 합치기 소리 어긋남 수정 (2026-10-24)
- 원인: 원본은 소리가 영상보다 0.08~0.11초 길다. 이어 붙일 때 소리는 원래 길이대로 이어지고 영상은 늘어나서, 파일이 늘수록 화면이 소리보다 늦게 나왔다(5개 합치면 약 0.33초). 인코딩이나 플레이어 속도 문제는 아님
- 수정: 합치기 때 파일마다 영상과 소리를 **영상 길이(vdur)** 에 맞춰 자른 뒤 이어 붙임. probe 에 `vdur` 저장(캐시도 vdur 있을 때만 사용)
- 검증(테스트 영상 5개, 영상 30.03초/소리 30.11초): 파일 시작 시각 30.03·60.06·90.09·120.12초에 영상이 정확히 맞고, 소리도 +0.209초 간격 그대로 맞음 (수정 전 0.33초 어긋남)
- 참고: 원본 MTS 는 소리가 영상보다 약 0.067초 먼저 시작함. 합치면서 두 스트림 시작을 0으로 맞춰서 이 차이는 파일 전체에 한 번만 생김(파일마다 쌓이지 않음). 필요하면 JYPlayer 의 소리 싱크 키로 조정

## JYPlayer 소리 싱크 조절 (2026-10-24)
- `.` = 소리 0.1초 늦춤, `,` = 0.1초 앞당김 (화면에 `소리 싱크 +0.3초`, 상태 줄에도 표시)
- 파일마다 따로 저장: 설정 json 의 `audio_delay` {파일 전체 경로: 초}. 다시 열면 자동 복원, 0으로 돌리면 기록 삭제. 저장은 0.5초 뒤 한 번(연타해도 디스크 한 번)
- 검증: 3번 `.`, 1번 `,` -> 0.2초 저장 -> 프로그램 재시작 후 같은 파일 0.2초 복원, 다른 파일은 0. 0으로 되돌리면 기록 삭제
